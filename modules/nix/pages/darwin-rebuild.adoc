= darwin-rebuild

`darwin-rebuild` is the primary command in *nix-darwin* for managing
macOS system configurations. It supports several subcommands (actions)
that control how the configuration is handled.

== *switch*

* *Most commonly used* subcommand.
* Builds the new system configuration (from your
`darwin-configuration.nix` or flake) *and activates* it immediately.
* Makes the new generation the current (boot/default) one.
* Applies changes like installing packages, updating `/etc` files,
restarting services, etc.
* Example: `sudo darwin-rebuild switch --flake .#my-flake`
* Requires `sudo` for system-level changes.

== *build*

* Builds the new system configuration but *does not activate* it.
* Results in a new generation in the store (e.g.,
`/nix/var/nix/profiles/system-123-link`), but the current system remains
unchanged.
* Useful for testing if the configuration builds successfully without
applying changes.
* You can later activate it manually or with another command.
* Example: `sudo darwin-rebuild build --flake .#my-flake`

== *activate*

* Activates a *previously built* system generation without rebuilding.
* Typically used on an existing built configuration (e.g., after
`build`, or on a remote system).
* Switches the system profile to point to that generation and runs the
activation script.
* Less commonly used directly.

== *check*

* Checks/validates the configuration during the build process (e.g.,
dry-run aspects or syntax).
* Builds the configuration (like `build`) but with additional checks for
issues.
* Often used to verify if the config is valid without full activation.
* Example: `sudo darwin-rebuild check --flake .#my-flake`

== *edit*

* Opens the current darwin configuration file in your default editor
(usually `$EDITOR`, like `vim` or `nano`).
* Intended for the classic non-flake setup where configuration is in
`~/.nixpkgs/darwin-configuration.nix` or similar.
* Allows quick editing before rebuilding.
* In modern flake-based setups, this is less relevant (people edit
`flake.nix` directly in their editor).

== *changelog*

* Displays or generates a changelog between the current and the new
configuration.
* Shows what changes would be made (e.g., added/removed packages,
modified settings).
* Useful for reviewing impacts before switching.
* Not as frequently mentioned in recent docs, but supported in the
script.

These subcommands are mutually exclusive—you choose one per invocation.
Many also accept common Nix flags like `--dry-run`, `--verbose`,
`--flake`, etc.

For the full list of options, run `darwin-rebuild --help`. Note that
with flakes (recommended), you usually include `--flake .#your-config`.

These behaviors mirror `nixos-rebuild` on NixOS, adapted for macOS. For
the latest details, check the nix-darwin source or run the help command
on your system.
