=== Quick Background for Nix Novices

* Nix → a powerful package manager that installs software in an
isolated, reproducible way (nothing interferes with your regular macOS
apps).
* Flakes → a modern way to organize Nix projects. A flake is like a
"`recipe book`" that declares exactly what versions of things to use, so
your setup is always the same.
* nix-darwin → like NixOS (which fully manages Linux systems), but for
macOS. It lets you declaratively configure parts of your Mac (users,
services, system settings, packages) using Nix code instead of clicking
around in System Settings.
* Determinate Nix → a improved, more reliable version of Nix created by
Determinate Systems. Their installer is faster, more stable on macOS
(e.g., survives OS upgrades), and comes with nice defaults. This
template is built to work well with it.

=== Apply nix config

==== 1. `sudo nix run nix-darwin -- switch --flake .#volt`

* This runs the *`darwin-rebuild`* tool *directly from the nix-darwin
flake* without needing it pre-installed on your system.
* `nix run nix-darwin` fetches and executes the `darwin-rebuild` app
from the official nix-darwin flake (usually the latest/master version).
* `--` passes the remaining arguments (`switch --flake ...`) to
`darwin-rebuild`.
* *When to use this*: Primarily for *initial installation* or
bootstrapping nix-darwin when `darwin-rebuild` is not yet available in
your PATH.
* After the first successful run, it installs `darwin-rebuild` into the
system profile, so you can use the simpler command next time.

==== 2. `sudo darwin-rebuild switch --flake .#volt`

* This uses the *`darwin-rebuild`* command *already installed* on your
system (typically from a previous nix-darwin activation).
* It’s the *standard command* for applying configuration changes after
the initial setup.
* *When to use this*: For everyday updates — e.g., after editing your
`flake.nix` or modules to add packages, users, services, etc.

==== Key Differences

[width="100%",cols="21%,41%,38%",options="header",]
|===
|Aspect |`nix run nix-darwin -- switch ...` |`darwin-rebuild switch ...`
|Requires pre-installed `darwin-rebuild`? |No (fetches it on-the-fly)
|Yes

|Typical use case |First-time setup/bootstrapping |Ongoing configuration
changes

|Performance |Slightly slower (fetches the tool each time if not cached)
|Faster (uses local installed version)

|Version of `darwin-rebuild` |Latest from the nix-darwin flake input
|The version from your current system generation
|===

=== nix run vs nix profile add

* Use nix run for one-off or occasional tools (e.g., trying something
new, running a specific version without cluttering your profile, or
scripts like your apply script). nix run is a temporary, on-demand way
to run a program from a Nix package (or flake output) without installing
it permanently into your user profile.
* Use nix profile install for everyday tools you want always available.

=== what about nix-shell?

Some programs you want to try by immediately running them. For example, if i want to try out the go-httpbin server, i would run:
`nix run nixpkgs#go-httpbin` - this will start httpbin for me and i can use it right away.

But what if I want to try a program that requires some setup or arguments? For example, if i wanted to try the `prettier` code formatter
i need to pipe some text to the program. This is where `nix-shell` becomes useful.

`nix-shell -p prettier` will give me a shell with prettier available in the path and i can now execute commands like `cat file.md | prettier parser=markdown` to see if i like it

if i decide i like prettier then i can nix profile add it or even better, update my home manager config.
