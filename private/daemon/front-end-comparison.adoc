Yes, *Rust {plus} WASM* is a strong option for your frontend, especially
with your requirements for *code sharing* between a desktop GUI and a
hosted web GUI (at www.mygui.com), while connecting to the same
remote/local daemon API.

The leading choice here is *Dioxus* (React-inspired), with alternatives
like *Leptos* (fine-grained reactivity, Signal-based) or *Yew* (older
but stable). These frameworks compile your Rust UI code to WASM for the
web version, and for desktop, they use a webview (similar to Tauri) to
run the same WASM-based UI natively. This gives near-perfect code
sharing—the UI logic, components, and state management stay identical,
with only minor config differences for local vs. remote daemon URLs.

==== How It Fits Your Architecture

Your UI code (in Rust) calls the daemon via HTTP/gRPC over TCP (e.g.,
using `reqwest` or framework-specific fetch). +
- Web version → Runs in browser as WASM. +
- Desktop version → Bundled with a lightweight webview renderer (Dioxus
uses Tao/WRY, same as Tauri). +
- No JS needed → Everything is pure Rust, avoiding the frontend/backend
split of traditional Tauri.

Dioxus excels here: one codebase for web {plus} desktop (and even
experimental mobile). It’s fullstack-capable, with hot-reloading and
good performance.

==== Recommendation

Go with *Dioxus* if you want to stay in Rust for the UI—it’s the closest
to "`Rust {plus} WASM frontend`" while supporting desktop natively, and
perfect for sharing with your hosted web GUI. +
Fall back to *Tauri* with a web frontend (e.g., Svelte/React/Vue) if you
prefer leveraging existing web ecosystems/components—it’s more mature,
slightly lighter, and proven for daemon-based apps. You could even use
Leptos/Dioxus inside Tauri for a hybrid Rust UI. +
Avoid Flutter/Qt unless you need true native widgets or mobile as a
priority (Flutter) or deep Qt integration (e.g., advanced graphics).

Both Dioxus and Tauri pair perfectly with your TCP/HTTP daemon setup.
Prototype a simple counter app connecting to your daemon in both—Dioxus
examples are straightforward. Let me know if you want starter code
